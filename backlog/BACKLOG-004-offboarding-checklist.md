## 描述

PM 想做新 feature：**「員工離職交接清單」**。

> ### 產品需求摘要（PM 給的）
>
> 員工提離職，主管要在系統內：
>
> 1. 看到該員工**管理的下屬**（要指派新主管）
> 2. 看到該員工**負責的進行中表單模板**（要重新指派負責人）
> 3. 看到該員工**還沒簽完的簽核單**（要跨權給代理人）
> 4. 看到該員工**最近 30 天用過的內部系統清單**（HR 通知 IT 收回權限）
>
> 上面 4 件事**全部完成**後，員工的離職交接才算完成。
>
> 員工最後在職日 D，**D 日 17:00 前**必須完成所有交接，否則自動進入「強制凍結」狀態。

PM 希望你（前端）這週給她：

1. UI 結構草案（不用畫，文字描述就好）
2. 跟後端要的 API 契約（你期望後端給你什麼 endpoint / payload）
3. 開發時程估計（大概幾個 sprint）
4. 你看到的風險（任何維度都可以）

**不需要寫任何 code**。這是規劃題。

## 提示

> **這題沒做不扣分**，做了我們會額外加分。
>
> **重點不是「想到多少功能」，是「想到多少 edge case」**。
>
> 例如：「主管離職，要交接給誰？」、「被指派的代理人也離職怎麼辦？」、
> 「員工 D 日撤回離職？」、「簽核單跨到 D+1 才回來？」、
> 「員工負責的『其中一個』表單模板是『離職交接清單』本身？」
>
> **能列出 8+ 個 edge case 而且分得出哪些必處理 / 哪些可忽略 / 哪些是後端責任 = 高分訊號**。
