# 歡迎加入 TubeHR Foundation Team — 你的第一天（前端組）

你今天加入 **TubeHR** 的 Foundation Team 前端組，負責 **FormAdmin**（表單管理後台）這個核心模組。

> 這份題目用來評估「前端工程師」的實務判斷與合作方式，不以年資或職稱作為硬門檻；職等會在面試後依交付深度與討論品質校準。

> **重要背景**：前一位主要前端工程師上週五緊急離職（家庭因素），交接時間不足。她留了一些工作項目跟一個待 review 的 PR，目前 Tech Lead 還在到處救火，**你要自己判斷怎麼開始**。

這是你的 onboarding 任務包。裡面有：

| 資料夾 | 內容 |
|--------|------|
| `codebase/` | FormAdmin 模組的核心程式碼（Next.js 14 + TypeScript + Jotai + Tailwind） |
| `team-chat/` | 團隊 Teams 頻道近兩週訊息（含上週離職前留下的對話） |
| `backlog/` | 4 張卡片：3 張待處理 + 1 張 ⭐ 加分題（規劃題） |
| `your-work/` | 你的工作區（內含空白模板，交付放這裡） |

---

## 你的任務

**用 3 小時，做你認為最重要的事。**

沒有規定順序，沒有必須完成的項目。你自己決定：
- 先讀什麼
- 做什麼、不做什麼
- 怎麼分配時間
- 怎麼判斷優先級

我們想看的是你**怎麼思考和工作**，不是你能做多快。

> **提示**：這份題目的設計是「**解決現有問題比做新東西更重要**」。BACKLOG-001 ~ 003 都是現有產品的真實問題，BACKLOG-004 ⭐ 是 0→1 規劃題（選做）。建議先處理問題，再評估時間挑戰 ⭐。

> **完成度高 better，但不全做不扣分**。我們更看重你「**選擇做什麼 + 為什麼**」的判斷力，而不是行數。

---

## 工具

你可以使用任何工具，包括：
- **AI 助手**（Claude / ChatGPT / Cursor / Copilot 等）— 我們鼓勵你用，這是 TubeHR R&D 文化
- **搜尋引擎**
- **任何你習慣的開發工具**

**唯一的要求**：在 `your-work/WORKLOG.md` 記錄你的工作過程，特別是：
- 你用 AI 用在哪
- AI 有沒有幫倒忙（給錯建議、漏 edge case、推坑）
- 你怎麼驗證 AI 的輸出

我們不是要看你「沒用 AI」，是要看你「用 AI 還能判斷對錯」。

---

## 交付

把所有產出放在 `your-work/` 資料夾。格式不限，但建議：

- `WORKLOG.md` — 你的工作日誌（**必須**）
- `QUESTIONS.md` — 你想釐清的問題（如果有）
- 修改後的 code（可以直接改 `codebase/` 內檔案，或在 `your-work/` 內放 patch / diff / 新檔案）
- 任何 PR 草稿、設計文件、架構圖

### WORKLOG 最少要回答

1. 你讀完資料後，**最先做的事是什麼？為什麼**？
2. 你做了哪些**取捨**（選擇做 A 而不是 B、選擇 mitigate 而不是 fix）？
3. 哪些地方你用了 **AI**？AI 有沒有幫倒忙？你怎麼識別？
4. 你看到的**問題清單**完整版（包含「看到但不做」的）+ 排序理由
5. 如果再給你 3 小時，**接下來會做什麼**？

## 環境提示

- 我們**不需要你跑起來**這個 codebase（節省你環境設定時間）
- 你可以直接讀 code、改 code、寫 patch、寫設計文件
- 如果你覺得某個檔案缺少 context，**在 QUESTIONS.md 列出來** — 「能問對問題」是我們很在意的訊號

---

## 面試時

我們會根據你的交付進行 **30~45 分鐘**的對談。重點不在「答對」，而在：

- 你**怎麼決定優先順序**（為什麼先做 A 不做 B）
- 你**怎麼在不確定的情況下推進**（看不到後端 API spec、看不到設計稿時怎麼辦）
- 你**怎麼跟團隊協作**（PR comment 的語氣、提出的問題、留給後端的訊息）
- 你**怎麼處理「不是你責任」的事**（前端遇到後端 bug 的當責態度）
- 你**怎麼善用 AI 又不被 AI 帶偏**（識別 AI 的盲點、做反向驗證）

祝你順利。
